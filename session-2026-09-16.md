## Key findings (verified this session)

- **Release is not obfuscated:** `androidApp/build.gradle.kts` has
  `isMinifyEnabled = false`.
- **Models ship in plaintext:** `shared/src/androidMain/assets/` has 13 `.tflite`.
  Only 2 are used at runtime (`ModelContract.DEFAULT_MODEL_ASSET` and
  `OPTIMIZED_MODEL_ASSET` = the `...ZoomOutV4` pair). Other 11 are dead weight.
- **litert 2.2.0 `CompiledModel` loads only from asset name or file path** - no
  in-memory/ByteBuffer loader. Verified via `javap` on the AAR.
- **The runtime AAR also ships classic `org.tensorflow.lite.Interpreter`, which
  has `Interpreter(ByteBuffer, Options)`** - this enables in-memory decryption on
  Android (requires rewriting `AndroidCatDogClassifier` off `CompiledModel`).
- **iOS** (`IosCatDogClassifier.kt`) uses the TFLite C API with
  `TfLiteModelCreateFromFile`; the C API also has `TfLiteModelCreate(data, size)`
  for in-memory loading. So iOS in-memory decryption is feasible too.
- **R8 is low risk:** app uses no reflection on its own classes; LiteRT/CameraX/
  Compose bring their own consumer ProGuard rules.
- **Performance reality check:** decryption is a **one-time cost at model load**,
  not per-frame. AES-GCM of 3.58 MB = **milliseconds, not seconds**. Per-frame
  inference (~2 ms) unchanged. The user's "few seconds" worry does not match the
  numbers (only a decrypt-to-file-every-launch design would be wasteful).
